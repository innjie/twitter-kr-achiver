# 사용 가이드 (User Guide) v1.10

> 대상: 이 앱을 다운로드하여 직접 설치·운영하는 사용자
> 목적: 실행 환경, 검색엔진, X API 연동을 본인 상황에 맞게 선택하고 설치, 보안 설정까지 완료

---

## 1. 시작 전 확인할 것

이 앱은 **완전 셀프호스팅** 도구입니다. 배포자는 코드만 제공하며, X API 키·데이터베이스·검색엔진은 모두 사용자 본인이 직접 설치하고 운영합니다. 따라서 아래 항목은 전적으로 사용자 책임입니다.

- 본인 명의의 X 개발자 계정 및 API 크레딧
- 본인 PC 또는 서버에 설치하는 데이터베이스, 검색엔진
- 개인정보 및 검색 데이터는 본인 환경에만 저장됨 (배포자는 접근 불가)
- **보안 설정(4장 참고)은 필수이며, 미설정 시 개인 아카이브가 외부에 노출될 수 있습니다**

---

## 2. 실행 환경 선택 (로컬 vs 서버)

### 비교표

| 항목 | 로컬 설치 | 서버(홈서버/VPS) 설치 |
|---|---|---|
| 대상 | 가끔 확인해도 되는 사용자 | 모바일로 언제든 확인하고 싶은 사용자 |
| 비용 | 0원 | 홈서버(장비비만) 또는 VPS(월 $5~10) |
| 데이터 갱신 | PC 켜져 있을 때만 폴링, 꺼져 있던 기간은 재실행 시 한 번에 채워짐 | 상시 폴링, 실시간에 가까움 |
| 외부 접속 | 불가 (같은 와이파이에서만) | Tailscale 또는 Cloudflare Tunnel로 가능 |
| 설정 난이도 | 낮음 | 중간 (상시 구동, 외부 접속 설정 필요) |
| 보안 고려사항 | 상대적으로 낮음 (외부 노출 없음) | **필수** (포트 노출, 인증 계층 등 4장 체크리스트 반드시 확인) |

### 선택 체크리스트
- "모바일에서 수시로 확인하고 싶다" → **서버형** 권장 (단, 보안 설정 필수)
- "집에서 가끔 검색만 하면 된다" → **로컬형**으로 충분

## 2-1. 로컬 설치 가이드

```bash
# 사전 준비: Docker Desktop 설치 (docker.com에서 다운로드)

# 프로젝트 클론
git clone <저장소_URL>
cd <프로젝트_폴더>

# 환경변수 설정
cp .env.example .env
# .env 파일을 열어 X API 키, DB_TYPE, SEARCH_ENGINE 등 설정

# 실행
docker compose up
```

- 실행 중에만 데이터가 수집됩니다. 앱을 끄면 폴링이 멈추고, 다시 켜면 그동안의 데이터를 한 번에 캐치업합니다.
- 데이터 유실 걱정은 없습니다. X 서버에 남아있던 내용을 재실행 시 가져옵니다.

## 2-2. 서버(홈서버/VPS) 설치 가이드

### VPS 예시
- Vultr, DigitalOcean 등 월 $5~10 수준의 저가 인스턴스로 충분

### 홈서버 예시
- 라즈베리파이 등 여분의 기기 + Tailscale(무료 VPN 방식)

### 공통 설치 단계

```bash
git clone <저장소_URL>
cd <프로젝트_폴더>/backend
cp ../.env.example .env
# .env 설정 (로컬과 동일 + APP_MODE=server, APP_USERNAME/PASSWORD 등 외부 접속 관련 설정 추가)
```

이후 검색엔진 profile(`server-meilisearch`/`server-elasticsearch`)에 **외부 접속 방식 profile을 최소 하나 추가**해서 실행합니다 — 외부 접속 방식 없이 검색엔진 profile만 켜면 백엔드가 어디서도 접근 불가능한 상태로만 뜹니다. 백엔드/검색엔진 모두 호스트에 포트를 노출하지 않으며(4-3 참고), 아래 셋 중 하나 이상을 선택하세요.

### 외부 접속 설정 (택1, 조합도 가능)
- **Tailscale**: 개인 VPN 메시 네트워크, 사설 네트워크 방식(본인 기기만 접속 가능) → **보안상 더 안전한 선택** (설치: 4-5-1)
- **Cloudflare Tunnel**: 공인 IP 없이 외부 노출 가능, 퍼블릭 터널 방식 → 반드시 인증 설정(4-5)과 함께 사용 (설치: 4-5-2)
- **Caddy 자동 HTTPS**: 본인 소유 공인 도메인을 이 서버로 직접 연결한 경우 (설치: 4-7)

모바일에서는 각 방식으로 접속한 뒤 해당 주소로 접속하면 됩니다.

## 3. 검색엔진 선택 (Meilisearch vs Elasticsearch)

### 비교표

| 항목 | Meilisearch | Elasticsearch |
|---|---|---|
| 설치 난이도 | 매우 낮음 | 중간~높음 (언어별 플러그인 설치 필요) |
| 리소스 요구량 | 낮음 (저사양 서버도 충분) | 높음 (최소 2GB+ 메모리 권장) |
| 한국어 검색 정확도 | 양호 | 매우 높음 (Nori 형태소 분석) |
| 다국어(영/일/중) 지원 | 자동 처리, 설정 불필요 | 언어별 플러그인 설치 후 최고 수준 정확도 |
| 비용 | 무료 | 무료 (Self-managed) |

### 선택 체크리스트
- "설정 없이 빠르게 시작하고 싶다" → **Meilisearch**
- "한국어/일본어/중국어 검색 정확도를 최고 수준으로 원하고, 설정에 시간을 투자할 수 있다" → **Elasticsearch**

---

## 3-1. Meilisearch 설치 가이드

```bash
# .env 설정
SEARCH_ENGINE=meilisearch

# Docker Compose로 실행 (프로젝트에 포함된 compose 파일 사용)
docker compose --profile meilisearch up -d
```

- 별도 설정 없이 한/영/일/중 문서를 자동 감지하여 처리합니다.
- 완료 후 앱 실행 시 자동으로 인덱싱이 시작됩니다.

> ⚠️ 보안: 반드시 4-1 항목(마스터키 설정)을 함께 진행하세요.

---

## 3-2. Elasticsearch 설치 가이드 (다국어 지원 포함)

```bash
# .env 설정
SEARCH_ENGINE=elasticsearch
ELASTIC_USERNAME=elastic
ELASTIC_PASSWORD=본인이_생성한_임의의_긴_문자열   # 4-2 참고

# Docker Compose로 실행 (프로젝트에 포함된 compose 파일 사용)
# 한국어/일본어/중국어 분석기 플러그인(Nori/Kuromoji/SmartCN)이 포함된
# 커스텀 이미지를 처음 실행 시 빌드하므로 --build를 붙입니다.
docker compose --profile elasticsearch up -d --build
```

**언어별 분석기 플러그인**
- `docker/elasticsearch.Dockerfile`이 빌드 시 자동으로 `analysis-nori`/`analysis-kuromoji`/`analysis-smartcn`을 설치합니다. 별도로 수동 설치할 필요는 없습니다.
- 영어(및 매핑되지 않은 그 외 언어)는 내장 standard analyzer를 사용하는 `text` 필드로 색인됩니다.

**주의사항**
- 위 플러그인은 모두 무료 오픈소스이며 별도 요금이 발생하지 않습니다.
- Elasticsearch 버전을 업그레이드할 경우(`docker/elasticsearch.Dockerfile`의 베이스 이미지 태그 변경), 재빌드가 필요합니다(`docker compose --profile elasticsearch up -d --build`).
- 인덱스 매핑(언어별 필드 `text_ko`/`text_ja`/`text_zh`/`text`에 각 analyzer 연결)은 앱이 최초 연결 시점에 자동으로 생성합니다. 별도 매핑 설정 파일을 직접 적용할 필요는 없습니다.

> ⚠️ 보안: 반드시 4-2 항목(보안 기능 활성화)을 함께 진행하세요. `docker-compose.yml`은 기본적으로 보안 기능이 켜진 채로 실행되지만, `ELASTIC_PASSWORD`를 설정하지 않으면 앱 자체가 실행되지 않습니다.

## 3-3. 검색엔진 전환 (스위칭) 방법

```bash
# .env 파일에서 아래 값만 변경 후 재시작
SEARCH_ENGINE=meilisearch   # 또는 elasticsearch

docker compose down
docker compose --profile <선택한 엔진> up -d
```

- **기존 DB(SQLite/Postgres)의 데이터는 그대로 유지되지만, 전환한 검색엔진의 인덱스는 비어 있는 상태로 시작합니다.** 검색엔진끼리는 서로 다른 별도 인덱스를 쓰기 때문에 자동으로 재인덱싱되지 않습니다.
- 전환 후 앱을 재시작한 다음, 아래 API를 한 번 호출해 DB 전체를 새 검색엔진에 재색인하세요.

```bash
curl -X POST http://127.0.0.1:3000/api/admin/reindex
# 서버 모드(Basic Auth 사용 시): curl -u 아이디:비밀번호 -X POST http://127.0.0.1:3000/api/admin/reindex
```

- 트윗 수가 많을수록 시간이 걸릴 수 있습니다(1,000건 단위로 순차 색인). 응답의 `indexed` 값으로 색인된 건수를 확인할 수 있습니다.

## 4. 보안 설정 체크리스트 (필수)

셀프호스팅 특성상 아래 항목을 놓치면 본인의 트윗 전문과 개인정보가 외부에 그대로 노출될 수 있습니다. 설치 직후 반드시 확인하세요.

### 4-1. Meilisearch 마스터키 설정

```bash
# .env에 마스터키 추가 (16자 이상 임의의 문자열)
MEILI_MASTER_KEY=본인이_생성한_임의의_긴_문자열
```

- 이 값이 없으면 누구나 API로 전체 검색 데이터를 조회·수정할 수 있습니다.
- 앱은 이 값이 없으면 실행되지 않도록 설계되어 있으니, 에러가 나면 이 항목부터 확인하세요.

### 4-2. Elasticsearch 보안 기능 활성화

```bash
# .env에 비밀번호를 먼저 설정한 뒤 컨테이너를 실행하면, 그 값으로 elastic 계정 비밀번호가 초기화됩니다.
ELASTIC_PASSWORD=본인이_생성한_임의의_긴_문자열
```

- 프로젝트의 `docker/docker-compose.yml`은 `xpack.security.enabled: "true"`가 이미 기본값으로 설정되어 있어 별도로 켤 필요가 없습니다.
- `ELASTIC_PASSWORD`가 `.env`에 없으면 앱 실행 자체가 차단됩니다(보안 필수 검증).

### 4-3. 포트 노출 제한

`docker-compose.yml`에서 검색엔진 포트 설정을 확인하세요.

```yaml
# 잘못된 예 (외부에서 접근 가능)
ports:
  - "7700:7700"

# 올바른 예 (본인 PC/서버 내부에서만 접근 가능)
ports:
  - "127.0.0.1:7700:7700"
```

- 서버(VPS)에 배포하는 경우 방화벽에서 검색엔진 포트(Meilisearch 7700, Elasticsearch 9200)를 **직접 열지 마세요**. 앱 백엔드를 통해서만 접근하도록 구성되어야 합니다.
- `docker-compose.server.yml` 오버레이를 쓰면 백엔드/검색엔진은 애초에 호스트 포트를 전혀 노출하지 않고(127.0.0.1 바인딩조차 없음) Docker 내부 네트워크로만 통신하며, 방화벽에서 열어야 할 포트는 `80`/`443`(Caddy)뿐입니다.

```bash
# VPS 방화벽 예시 (ufw)
sudo ufw allow 22      # SSH
sudo ufw allow 443     # HTTPS (앱 접속용)
sudo ufw enable
# 7700, 9200 포트는 열지 않음
```

### 4-4. .env / 시크릿 파일 관리

- `.env` 파일 권한 제한:
```bash
chmod 600 .env
```
- 실수로 git에 커밋된 적이 있다면 단순 삭제 커밋으로는 부족합니다. `git filter-repo` 또는 BFG Repo-Cleaner로 히스토리에서 완전히 제거하고, 해당 API 키/토큰은 **반드시 재발급(폐기 후 재발급)** 받으세요.

### 4-5. 서버 모드 외부 접속 시 인증 계층

Cloudflare Tunnel처럼 공인 URL을 발급받는 방식은 URL만 알면 누구나 접속 가능합니다. 반드시 아래 중 하나를 적용하세요.

```bash
# .env에 앱 로그인 계정 설정
APP_USERNAME=본인이_정한_아이디
APP_PASSWORD=본인이_정한_비밀번호
```

- Tailscale 사용 시에는 사설 네트워크 방식이라 상대적으로 안전하지만, 그래도 위 계정 설정을 함께 해두는 것을 권장합니다.

#### 4-5-1. Tailscale 계정 발급 및 로그인 (사설 네트워크, 권장)

1. [tailscale.com](https://tailscale.com) 접속 → 구글/깃허브/마이크로소프트 계정 등으로 로그인(무료 플랜으로 개인 기기 여러 대 충분)
   - 로그인 직후 "Next, add a second device" 같은 온보딩 화면이 뜰 수 있는데, 이건 앱 설치를 유도하는 화면일 뿐 에러가 아닙니다. 서버는 이 화면으로 추가하는 게 아니라 아래 2번의 auth key로 헤드리스 인증하므로 그냥 닫고 넘어가면 됩니다.
2. [관리 콘솔 → Settings → Keys](https://login.tailscale.com/admin/settings/keys)에서 **Generate auth key** 클릭
   - **Reusable: ON** — 컨테이너를 재생성(이미지 재빌드, `down`/`up` 등)할 때마다 같은 키로 다시 인증할 수 있어야 하므로 켭니다.
   - **Ephemeral: OFF** — 켜두면 연결이 끊기는 순간 tailnet에서 노드가 자동 삭제됩니다. 서버는 재시작 중 잠깐 끊겨도 같은 노드로 남아있어야 하므로 끕니다.
   - **Expiration**: 이 키는 최초 인증(및 컨테이너 재생성 시 재인증)에만 쓰이는 용도라 크게 중요하지 않음 — 기본값(보통 90일)으로 두면 됩니다.
   - 생성된 키(`tskey-auth-...`)를 복사 — 이 화면을 벗어나면 다시 볼 수 없음
3. `.env`에 설정:
   ```bash
   TS_AUTHKEY=tskey-auth-여기에_발급받은_값
   TS_HOSTNAME=twitter-kr-achiver   # 선택, 탈넷에 표시될 이름
   ```
4. 서버 프로필 실행:
   ```bash
   cd docker
   docker compose -f docker-compose.yml -f docker-compose.server.yml \
     --profile server-meilisearch --profile tailscale --env-file ../backend/.env up -d
   ```
5. **최초 1회만** 아래 명령으로 이 서버를 tailnet에 노출(이후 재시작 시엔 다시 실행할 필요 없음 — tailscaled 상태가 볼륨에 저장됨):
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.server.yml exec tailscale \
     tailscale serve --bg https / http://backend:3000
   ```
6. 접속할 기기(스마트폰 등)에도 Tailscale 앱을 설치하고 같은 계정으로 로그인하면, [관리 콘솔](https://login.tailscale.com/admin/machines)에 나타나는 이 서버의 tailnet 주소(`https://twitter-kr-achiver.<tailnet이름>.ts.net`)로 접속할 수 있습니다.
7. **[관리 콘솔 → Machines](https://login.tailscale.com/admin/machines)**에서 방금 등록된 이 서버 노드를 찾아 `...` 메뉴 → **Disable key expiry** 클릭. auth key의 만료와는 별개로 노드(기기) 세션 자체가 기본 정책상 약 180일마다 재인증을 요구하는데, 서버는 대화형으로 다시 로그인할 방법이 없어 방치하면 어느 날 갑자기 연결이 끊깁니다 — 이 설정으로 방지합니다.

#### 4-5-2. Cloudflare Tunnel 계정 발급 및 터널 생성

1. [Cloudflare 가입](https://dash.cloudflare.com/sign-up) 후 로그인 (도메인이 없어도 Zero Trust는 무료로 사용 가능한 범위가 있으나, Public Hostname을 붙이려면 Cloudflare에 연결된 본인 소유 도메인이 필요합니다)
2. Cloudflare 대시보드 → **Zero Trust** → **Networks → Tunnels** → **Create a tunnel** → Cloudflared 선택 → 터널 이름 지정
3. 발급된 토큰(긴 문자열)을 `.env`에 설정:
   ```bash
   CLOUDFLARE_TUNNEL_TOKEN=여기에_발급받은_토큰
   ```
4. 같은 화면의 **Public Hostname** 탭에서 라우팅 설정: 원하는 서브도메인(예: `archive.본인도메인.com`) → Service 타입 `HTTP`, URL `backend:3000` (docker 내부 네트워크 이름이므로 컨테이너가 이미 떠 있어야 이 값이 정상 동작을 확인할 수 있습니다)
5. 서버 프로필 실행:
   ```bash
   cd docker
   docker compose -f docker-compose.yml -f docker-compose.server.yml \
     --profile server-meilisearch --profile cloudflare-tunnel --env-file ../backend/.env up -d
   ```
6. Cloudflare 대시보드의 터널 상태가 **Healthy**로 바뀌면 3번에서 설정한 주소로 외부에서 접속 가능합니다. 이 방식은 URL만 알면 누구나 접속 가능하므로 위 `APP_USERNAME`/`APP_PASSWORD` 설정을 **반드시** 함께 적용하세요.

### 4-6. DB 파일 보호

```bash
# DB 파일 권한 제한 (설치 스크립트가 자동 설정하지만 직접 확인 권장)
chmod 600 ./data/archive.db
```

- DB 파일이 웹서버의 정적 파일 제공 경로(예: `public/`, `static/`) 안에 있지 않은지 확인하세요.

### 4-7. HTTPS 적용 (VPS + 직접 도메인 사용 시)

- `docker/docker-compose.server.yml` 오버레이에 포함된 Caddy가 Let's Encrypt 인증서를 자동 발급/갱신합니다.
```bash
# .env에 실제 이 서버를 가리키는 도메인 설정
DOMAIN=example.com

cd docker
docker compose -f docker-compose.yml -f docker-compose.server.yml \
  --profile server-meilisearch --profile https --env-file ../backend/.env up -d
```
- `DOMAIN`을 설정하지 않으면 `localhost` 기준 자체 서명 인증서로 동작합니다(공인 브라우저에서는 인증서 경고가 뜨는 게 정상 — 이 경우는 그냥 4-5-1의 Tailscale을 쓰는 게 더 낫습니다). 실제 Let's Encrypt 발급을 받으려면 `DOMAIN`이 이 서버의 공인 IP를 실제로 가리키고 있어야 하고, 80/443 포트가 방화벽에서 열려 있어야 합니다.
- Tailscale/Cloudflare Tunnel을 쓰는 경우 각자 자체적으로 암호화/HTTPS 종단을 하므로 `https` profile(Caddy)은 필요 없습니다(4-5-1, 4-5-2 참고).

## 5. X API 연동 (BYOK)

### 5-1. 개발자 계정 생성
1. developer.x.com 접속 → 본인 X 계정으로 로그인 (무료 계정도 가능, 이메일/전화 인증 필요)
2. 개발자 계정 신청 → 승인 후 프로젝트/앱 생성

### 5-2. OAuth 앱 등록
앱 생성 후 반드시 **"User authentication settings"**를 켜야 OAuth 2.0 Client ID/Secret이 발급됩니다.
- **App permissions**: `Read` (트윗/좋아요/북마크 조회만 하므로 쓰기 권한 불필요)
- **Type of App**: `Web App, Automated App or Bot` (Client Secret을 함께 쓰는 confidential client 방식)
- **Callback URI / Redirect URL**: `.env`의 `X_REDIRECT_URI` 값과 **정확히 동일**하게 입력 (기본값: `http://127.0.0.1:3000/auth/callback`, 포트를 바꿨다면 그에 맞게 조정). 한 글자라도 다르면 X가 콜백을 거부합니다.
- **Website URL**: 공개 서비스가 아니어도 되니 아무 URL이나(예: 본인 GitHub 저장소 주소) 입력
- 저장 후 **Keys and tokens** 탭에서 OAuth 2.0 Client ID/Client Secret 발급 (Client Secret은 그 화면을 벗어나면 다시 못 볼 수 있으니 바로 복사)

### 5-3. 크레딧 충전
- 개발자 콘솔에서 소액 크레딧 충전 (본인 계정 데이터만 다루는 경우 월 1~수 달러 수준)
- 북마크(bookmarks) 엔드포인트는 X 쪽 접근 등급에 따라 제한될 수 있으니, 앱의 Access Level 페이지에서 Bookmarks 포함 여부를 미리 확인해두면 좋습니다.

### 5-4. `.env` 설정
`backend/.env`(없다면 `.env.example`을 복사해서 생성, git에는 올라가지 않는 개인 설정 파일)에 아래 값을 채웁니다.

| 변수 | 값 |
|---|---|
| `X_CLIENT_ID` | 5-2에서 발급받은 Client ID |
| `X_CLIENT_SECRET` | 5-2에서 발급받은 Client Secret |
| `X_REDIRECT_URI` | 5-2에 등록한 Callback URI와 동일한 값 (기본값 그대로면 수정 불필요) |
| `TOKEN_ENCRYPTION_KEY` | 아래 커맨드로 새로 생성 (사용자마다 반드시 다른 값을 써야 함 — 이 키로 저장된 Refresh Token이 암호화되므로, 남과 같은 값이나 예시값을 그대로 쓰면 안 됩니다) |

```bash
# TOKEN_ENCRYPTION_KEY 생성 (AES-256용 32바이트를 hex로 표현, 64자)
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> X Premium(파란 배지) 구독은 필요하지 않습니다. 개발자 계정 등록과 크레딧 충전만으로 충분합니다.

### 5-5. 앱에 연동
1. 앱(백엔드 서버) 실행 후 브라우저에서 `/auth/login` 접속 (예: `http://127.0.0.1:3000/auth/login`)
2. X 로그인 화면으로 자동 이동 → 로그인 및 권한 승인
3. 승인 후 자동으로 콜백 처리되어 "X 계정 연동이 완료되었습니다" 메시지가 표시되면 완료 (연동 여부는 `/auth/status`에서도 확인 가능)
4. 연동 완료 후에는 5-6의 최초 데이터 임포트를 먼저 진행하세요 (API는 최근 데이터만 가져올 수 있습니다)

> 현재는 프론트엔드에 "X 계정 연동" 버튼이 아직 없어 위 주소를 직접 열어야 합니다. 추후 검색 화면에 연동 버튼이 추가되면 이 과정이 자동화될 예정입니다.

### 5-6. 최초 데이터 임포트 (아카이브 백필)

X API는 **최근 3,200개 트윗까지만** 조회할 수 있습니다. 계정을 오래 사용했거나 트윗 수가 많다면(예: 수만~수십만 건), 과거 이력은 API로 가져올 수 없으므로 **X 공식 데이터 아카이브**로 최초 1회 임포트해야 합니다.

**진행 순서**

1. X 앱/웹의 설정 > "계정" > "데이터 다운로드"에서 아카이브 요청
   - 트윗 수가 많을수록 X 측에서 파일을 준비하는 데 **몇 시간~며칠**이 걸릴 수 있습니다. 미리 요청해두는 것을 권장합니다.
2. 준비 완료 알림(이메일 등)을 받으면 zip 파일 다운로드
3. 앱 실행 후 브라우저에서 `/import.html` 접속 → "본인 X 아이디"(@ 제외, 영문/숫자/밑줄)를 입력하고 다운로드한 zip 파일 선택 후 업로드
   - 아이디를 직접 입력받는 이유: 아카이브의 `tweet.js`에는 본인 계정의 아이디가 들어있지 않아, 본인이 작성한 트윗의 작성자 정보를 채우려면 별도로 입력이 필요합니다.
4. 업로드 진행률과 처리 결과(임포트/스킵 건수)가 화면에 표시됩니다. 업로드가 끝난 zip 파일은 처리 후 서버에서 즉시 삭제되어 디스크에 남지 않습니다.

| 트윗 규모 | 예상 임포트 소요 시간 (로컬 PC 기준) |
|---|---|
| 수천 건 | 1분 이내 |
| 수만 건 | 수 분 |
| 10만~20만 건 이상 | 수십 분 내외 |

- 임포트가 끝나면 검색엔진 인덱싱도 자동으로 함께 진행됩니다.
- 임포트 완료 후부터는 X API 폴링이 자동으로 시작되어, 그 이후에 작성한 신규 트윗/리트윗/좋아요/북마크만 계속 수집됩니다.
- **아카이브 임포트는 API를 사용하지 않으므로 API 크레딧이 소모되지 않습니다.**
- **알려진 제약**: X 공식 아카이브의 "좋아요" 항목에는 실제로 좋아요를 누른 시각이 포함되어 있지 않습니다. 이 앱은 해당 항목의 날짜를 임포트 실행 시각으로 대신 표시합니다(검색/필터링에는 영향 없음, 정렬 시 날짜만 근사치).

## 6. 고급 검색 문법 사용법

이 앱의 검색창에서는 X(트위터)의 고급 검색과 유사한 문법을 사용할 수 있습니다. 검색어와 함께 아래 문법을 조합해서 입력하면 됩니다.

| 문법 | 설명 | 예시 |
|---|---|---|
| `from:계정명` | 특정 작성자 글만 검색 | `김치찌개 from:hongildong` |
| `since:YYYY-MM-DD` | 해당 날짜 이후 글만 검색 | `여행 since:2025-01-01` |
| `until:YYYY-MM-DD` | 해당 날짜 이전 글만 검색 | `여행 until:2025-06-30` |
| `lang:ko` / `en` / `ja` / `zh` | 특정 언어로 작성된 글만 검색 | `날씨 lang:ja` |
| `is:tweet` / `retweet` / `like` / `bookmark` | 해당 종류의 글만 검색 | `is:retweet 뉴스` |
| `is:reply` | 답글만 검색 (다른 종류 필터와 동시 사용 가능, 예: `is:retweet is:reply`) | `is:reply` |

**조합 사용 예시**
```
맛집 from:hongildong since:2025-01-01 until:2025-06-30 lang:ko
```
→ "hongildong" 계정이 2025년 1월 1일부터 6월 30일 사이에 한국어로 작성한 글 중 "맛집"이 포함된 글만 검색

**참고**
- 이 문법은 검색엔진(Meilisearch/Elasticsearch) 종류와 무관하게 동일하게 동작합니다. 앱 내부에서 문법을 해석해 검색엔진에 맞는 필터 조건으로 자동 변환하기 때문입니다.
- 날짜 형식은 `YYYY-MM-DD`만 지원합니다.
- `lang:` 값은 소문자로 입력하세요 (`lang:ko`는 되지만 `lang:KO`는 결과가 0건으로 나옵니다). 모바일에서 자동 대문자화(autocapitalize) 때문에 의도치 않게 대문자가 섞일 수 있으니 주의하세요.
- `is:reply`는 X 아카이브에 답글 표시(`in_reply_to_status_id`)가 있는 글만 대상으로 하며, `is:tweet`/`retweet`/`like`/`bookmark`와는 별개 조건이라 함께 사용할 수 있습니다.

## 7. 트러블슈팅

| 증상 | 원인/해결 |
|---|---|
| `docker compose up` 실패 | Docker Desktop이 실행 중인지 확인 |
| X API 인증 실패 | Redirect URI가 개발자 콘솔 설정과 정확히 일치하는지 확인 |
| Elasticsearch 실행 안 됨 | 플러그인 버전이 Elasticsearch 버전과 일치하는지 확인 |
| 모바일에서 서버 접속 안 됨 | Tailscale/Cloudflare Tunnel 연결 상태 확인 |
| 데이터가 갱신되지 않음 | 로컬 설치의 경우 앱이 실행 중인지 확인 (꺼져 있으면 폴링 중단) |
| 검색엔진 실행 시 인증 에러 | `MEILI_MASTER_KEY` 또는 `ELASTIC_PASSWORD` 설정 여부 확인 |
| 외부에서 아카이브가 열람됨 | 4-3(포트 노출), 4-5(인증 계층) 설정 여부 즉시 확인 |
| `from:`/`since:`/`until:` 검색이 안 됨 | 날짜 형식(`YYYY-MM-DD`)이 정확한지, 계정명에 오타가 없는지 확인 |
