# 사용 가이드 (User Guide) v1.3

> 대상: 이 앱을 다운로드하여 직접 설치·운영하는 사용자
> 목적: 실행 환경, 검색엔진, X API 연동을 본인 상황에 맞게 선택하고 설치, 보안 설정까지 완료

---

## 1. 시작 전 확인할 것

이 앱은 **완전 셀프호스팅** 도구입니다. 배포자는 코드만 제공하며, X API 키·데이터베이스·검색엔진은 모두 사용자 본인이 직접 설치하고 운영합니다. 따라서 아래 항목은 전적으로 사용자 책임입니다.

- 본인 명의의 X 개발자 계정 및 API 크레딧
- 본인 PC 또는 서버에 설치하는 데이터베이스, 검색엔진
- 개인정보 및 검색 데이터는 본인 환경에만 저장됨 (배포자는 접근 불가)
- **보안 설정(4장 참고)은 필수이며, 미설정 시 개인 아카이브가 외부에 노출될 수 있습니다**

---

## 2. 실행 환경 선택 (로컬 vs 서버)

### 비교표

| 항목 | 로컬 설치 | 서버(홈서버/VPS) 설치 |
|---|---|---|
| 대상 | 가끔 확인해도 되는 사용자 | 모바일로 언제든 확인하고 싶은 사용자 |
| 비용 | 0원 | 홈서버(장비비만) 또는 VPS(월 $5~10) |
| 데이터 갱신 | PC 켜져 있을 때만 폴링, 꺼져 있던 기간은 재실행 시 한 번에 채워짐 | 상시 폴링, 실시간에 가까움 |
| 외부 접속 | 불가 (같은 와이파이에서만) | Tailscale 또는 Cloudflare Tunnel로 가능 |
| 설정 난이도 | 낮음 | 중간 (상시 구동, 외부 접속 설정 필요) |
| 보안 고려사항 | 상대적으로 낮음 (외부 노출 없음) | **필수** (포트 노출, 인증 계층 등 4장 체크리스트 반드시 확인) |

### 선택 체크리스트
- "모바일에서 수시로 확인하고 싶다" → **서버형** 권장 (단, 보안 설정 필수)
- "집에서 가끔 검색만 하면 된다" → **로컬형**으로 충분

## 2-1. 로컬 설치 가이드

```bash
# 사전 준비: Docker Desktop 설치 (docker.com에서 다운로드)

# 프로젝트 클론
git clone <저장소_URL>
cd <프로젝트_폴더>

# 환경변수 설정
cp .env.example .env
# .env 파일을 열어 X API 키, DB_TYPE, SEARCH_ENGINE 등 설정

# 실행
docker compose up
```

- 실행 중에만 데이터가 수집됩니다. 앱을 끄면 폴링이 멈추고, 다시 켜면 그동안의 데이터를 한 번에 캐치업합니다.
- 데이터 유실 걱정은 없습니다. X 서버에 남아있던 내용을 재실행 시 가져옵니다.

## 2-2. 서버(홈서버/VPS) 설치 가이드

### VPS 예시
- Vultr, DigitalOcean 등 월 $5~10 수준의 저가 인스턴스로 충분

### 홈서버 예시
- 라즈베리파이 등 여분의 기기 + Tailscale(무료 VPN 방식)

### 공통 설치 단계

```bash
git clone <저장소_URL>
cd <프로젝트_폴더>
cp .env.example .env
# .env 설정 (로컬과 동일 + 외부 접속 관련 설정 추가)

# 상시 구동 (재부팅 시 자동 시작 설정 포함)
docker compose up -d
```

### 외부 접속 설정 (택1)
- **Tailscale**: 개인 VPN 메시 네트워크, 설정 간단, 사설 네트워크 방식(본인 기기만 접속 가능) → **보안상 더 안전한 선택**
- **Cloudflare Tunnel**: 공인 IP 없이 외부 노출 가능, 퍼블릭 터널 방식 → 반드시 4-3 인증 설정과 함께 사용

각 서비스 공식 문서를 따라 설치 후, 모바일에서 해당 주소로 접속하면 됩니다.

## 3. 검색엔진 선택 (Meilisearch vs Elasticsearch)

### 비교표

| 항목 | Meilisearch | Elasticsearch |
|---|---|---|
| 설치 난이도 | 매우 낮음 | 중간~높음 (언어별 플러그인 설치 필요) |
| 리소스 요구량 | 낮음 (저사양 서버도 충분) | 높음 (최소 2GB+ 메모리 권장) |
| 한국어 검색 정확도 | 양호 | 매우 높음 (Nori 형태소 분석) |
| 다국어(영/일/중) 지원 | 자동 처리, 설정 불필요 | 언어별 플러그인 설치 후 최고 수준 정확도 |
| 비용 | 무료 | 무료 (Self-managed) |

### 선택 체크리스트
- "설정 없이 빠르게 시작하고 싶다" → **Meilisearch**
- "한국어/일본어/중국어 검색 정확도를 최고 수준으로 원하고, 설정에 시간을 투자할 수 있다" → **Elasticsearch**

---

## 3-1. Meilisearch 설치 가이드

```bash
# .env 설정
SEARCH_ENGINE=meilisearch

# Docker Compose로 실행 (프로젝트에 포함된 compose 파일 사용)
docker compose --profile meilisearch up -d
```

- 별도 설정 없이 한/영/일/중 문서를 자동 감지하여 처리합니다.
- 완료 후 앱 실행 시 자동으로 인덱싱이 시작됩니다.

> ⚠️ 보안: 반드시 4-1 항목(마스터키 설정)을 함께 진행하세요.

---

## 3-2. Elasticsearch 설치 가이드 (다국어 지원 포함)

```bash
# .env 설정
SEARCH_ENGINE=elasticsearch

# 로컬 Docker로 Elasticsearch 실행
curl -fsSL https://elastic.co/start-local | sh
```

**언어별 분석기 플러그인 설치**

```bash
# 한국어
bin/elasticsearch-plugin install analysis-nori

# 일본어
bin/elasticsearch-plugin install analysis-kuromoji

# 중국어
bin/elasticsearch-plugin install analysis-smartcn
# 영어는 내장 analyzer라 별도 설치 불필요
```

**주의사항**
- 위 플러그인은 모두 무료 오픈소스이며 별도 요금이 발생하지 않습니다.
- Elasticsearch 버전을 업그레이드할 경우, 설치된 플러그인도 반드시 동일 버전으로 재설치해야 합니다. 버전이 맞지 않으면 실행이 되지 않습니다.
- 프로젝트가 제공하는 인덱스 매핑 설정 파일을 그대로 적용하면 언어별 필드(`text_ko`, `text_ja`, `text_zh`, `text_en`)에 각 analyzer가 자동으로 연결됩니다. 별도 매핑 설정은 필요하지 않습니다.

> ⚠️ 보안: 반드시 4-2 항목(보안 기능 활성화)을 함께 진행하세요. 기본 설치 스크립트는 보안이 꺼진 채로 실행되는 경우가 있습니다.

## 3-3. 검색엔진 전환 (스위칭) 방법

```bash
# .env 파일에서 아래 값만 변경 후 재시작
SEARCH_ENGINE=meilisearch   # 또는 elasticsearch

docker compose down
docker compose --profile <선택한 엔진> up -d
```

- 기존에 인덱싱된 데이터는 유지되며, 전환 시 재인덱싱이 자동으로 진행됩니다.

## 4. 보안 설정 체크리스트 (필수)

셀프호스팅 특성상 아래 항목을 놓치면 본인의 트윗 전문과 개인정보가 외부에 그대로 노출될 수 있습니다. 설치 직후 반드시 확인하세요.

### 4-1. Meilisearch 마스터키 설정

```bash
# .env에 마스터키 추가 (16자 이상 임의의 문자열)
MEILI_MASTER_KEY=본인이_생성한_임의의_긴_문자열
```

- 이 값이 없으면 누구나 API로 전체 검색 데이터를 조회·수정할 수 있습니다.
- 앱은 이 값이 없으면 실행되지 않도록 설계되어 있으니, 에러가 나면 이 항목부터 확인하세요.

### 4-2. Elasticsearch 보안 기능 활성화

```bash
# 최초 실행 후 비밀번호 설정
bin/elasticsearch-reset-password -u elastic
```

- 출력된 비밀번호를 `.env`의 `ELASTIC_PASSWORD`에 저장
- `elasticsearch.yml`에서 `xpack.security.enabled: true` 확인 (기본값이 꺼져 있는 배포판도 있으므로 직접 확인 필요)

### 4-3. 포트 노출 제한

`docker-compose.yml`에서 검색엔진 포트 설정을 확인하세요.

```yaml
# 잘못된 예 (외부에서 접근 가능)
ports:
  - "7700:7700"

# 올바른 예 (본인 PC/서버 내부에서만 접근 가능)
ports:
  - "127.0.0.1:7700:7700"
```

- 서버(VPS)에 배포하는 경우 방화벽에서 검색엔진 포트(Meilisearch 7700, Elasticsearch 9200)를 **직접 열지 마세요**. 앱 백엔드를 통해서만 접근하도록 구성되어야 합니다.

```bash
# VPS 방화벽 예시 (ufw)
sudo ufw allow 22      # SSH
sudo ufw allow 443     # HTTPS (앱 접속용)
sudo ufw enable
# 7700, 9200 포트는 열지 않음
```

### 4-4. .env / 시크릿 파일 관리

- `.env` 파일 권한 제한:
```bash
chmod 600 .env
```
- 실수로 git에 커밋된 적이 있다면 단순 삭제 커밋으로는 부족합니다. `git filter-repo` 또는 BFG Repo-Cleaner로 히스토리에서 완전히 제거하고, 해당 API 키/토큰은 **반드시 재발급(폐기 후 재발급)** 받으세요.

### 4-5. 서버 모드 외부 접속 시 인증 계층

Cloudflare Tunnel처럼 공인 URL을 발급받는 방식은 URL만 알면 누구나 접속 가능합니다. 반드시 아래 중 하나를 적용하세요.

```bash
# .env에 앱 로그인 계정 설정
APP_USERNAME=본인이_정한_아이디
APP_PASSWORD=본인이_정한_비밀번호
```

- Tailscale 사용 시에는 사설 네트워크 방식이라 상대적으로 안전하지만, 그래도 위 계정 설정을 함께 해두는 것을 권장합니다.

### 4-6. DB 파일 보호

```bash
# DB 파일 권한 제한 (설치 스크립트가 자동 설정하지만 직접 확인 권장)
chmod 600 ./data/archive.db
```

- DB 파일이 웹서버의 정적 파일 제공 경로(예: `public/`, `static/`) 안에 있지 않은지 확인하세요.

### 4-7. HTTPS 적용 (VPS + 직접 도메인 사용 시)

- 프로젝트에서 기본 제공하는 Caddy 설정을 사용하면 Let's Encrypt 인증서가 자동 발급/갱신됩니다.
```bash
docker compose --profile server up -d
# Caddy가 포함된 프로필이며, 도메인만 .env(DOMAIN=example.com)에 설정하면 자동으로 HTTPS 적용
```
- Cloudflare Tunnel 사용 시에는 기본적으로 HTTPS가 자동 적용되므로 별도 설정 불필요

## 5. X API 연동 (BYOK)

### 5-1. 개발자 계정 생성
1. developer.x.com 접속 → 본인 X 계정으로 로그인 (무료 계정도 가능, 이메일/전화 인증 필요)
2. 개발자 계정 신청 → 승인 후 프로젝트/앱 생성

### 5-2. OAuth 앱 등록
- 앱 생성 시 인증 방식은 **OAuth 2.0 (PKCE 권장)** 선택
- Redirect URI에 앱의 콜백 주소를 **정확히 일치**하도록 입력 (로컬: `http://localhost:PORT/callback`, 서버: 본인 도메인/터널 주소)

### 5-3. 크레딧 충전
- 개발자 콘솔에서 소액 크레딧 충전 (본인 계정 데이터만 다루는 경우 월 1~수 달러 수준)

### 5-4. 앱에 연동
1. 앱 실행 후 "X 계정 연동" 버튼 클릭
2. OAuth 인증 화면에서 권한 승인
3. 연동 완료 후에는 5-5의 최초 데이터 임포트를 먼저 진행하세요 (API는 최근 데이터만 가져올 수 있습니다)

> X Premium(파란 배지) 구독은 필요하지 않습니다. 개발자 계정 등록과 크레딧 충전만으로 충분합니다.

### 5-5. 최초 데이터 임포트 (아카이브 백필)

X API는 **최근 3,200개 트윗까지만** 조회할 수 있습니다. 계정을 오래 사용했거나 트윗 수가 많다면(예: 수만~수십만 건), 과거 이력은 API로 가져올 수 없으므로 **X 공식 데이터 아카이브**로 최초 1회 임포트해야 합니다.

**진행 순서**

1. X 앱/웹의 설정 > "계정" > "데이터 다운로드"에서 아카이브 요청
   - 트윗 수가 많을수록 X 측에서 파일을 준비하는 데 **몇 시간~며칠**이 걸릴 수 있습니다. 미리 요청해두는 것을 권장합니다.
2. 준비 완료 알림(이메일 등)을 받으면 zip 파일 다운로드
3. 앱의 "아카이브 임포트" 메뉴에서 다운로드한 zip 파일 업로드
4. 임포트 진행 (트윗 수에 따라 소요 시간 다름)

| 트윗 규모 | 예상 임포트 소요 시간 (로컬 PC 기준) |
|---|---|
| 수천 건 | 1분 이내 |
| 수만 건 | 수 분 |
| 10만~20만 건 이상 | 수십 분 내외 |

- 임포트가 끝나면 검색엔진 인덱싱도 자동으로 함께 진행됩니다.
- 임포트 완료 후부터는 X API 폴링이 자동으로 시작되어, 그 이후에 작성한 신규 트윗/리트윗/좋아요/북마크만 계속 수집됩니다.
- **아카이브 임포트는 API를 사용하지 않으므로 API 크레딧이 소모되지 않습니다.**

## 6. 고급 검색 문법 사용법

이 앱의 검색창에서는 X(트위터)의 고급 검색과 유사한 문법을 사용할 수 있습니다. 검색어와 함께 아래 문법을 조합해서 입력하면 됩니다.

| 문법 | 설명 | 예시 |
|---|---|---|
| `from:계정명` | 특정 작성자 글만 검색 | `김치찌개 from:hongildong` |
| `since:YYYY-MM-DD` | 해당 날짜 이후 글만 검색 | `여행 since:2025-01-01` |
| `until:YYYY-MM-DD` | 해당 날짜 이전 글만 검색 | `여행 until:2025-06-30` |
| `lang:ko` / `en` / `ja` / `zh` | 특정 언어로 작성된 글만 검색 | `날씨 lang:ja` |
| `is:retweet` | 리트윗만 검색 | `is:retweet 뉴스` |
| `is:reply` | 답글만 검색 | `is:reply` |

**조합 사용 예시**
```
맛집 from:hongildong since:2025-01-01 until:2025-06-30 lang:ko
```
→ "hongildong" 계정이 2025년 1월 1일부터 6월 30일 사이에 한국어로 작성한 글 중 "맛집"이 포함된 글만 검색

**참고**
- 이 문법은 검색엔진(Meilisearch/Elasticsearch) 종류와 무관하게 동일하게 동작합니다. 앱 내부에서 문법을 해석해 검색엔진에 맞는 필터 조건으로 자동 변환하기 때문입니다.
- 날짜 형식은 `YYYY-MM-DD`만 지원합니다.

## 7. 트러블슈팅

| 증상 | 원인/해결 |
|---|---|
| `docker compose up` 실패 | Docker Desktop이 실행 중인지 확인 |
| X API 인증 실패 | Redirect URI가 개발자 콘솔 설정과 정확히 일치하는지 확인 |
| Elasticsearch 실행 안 됨 | 플러그인 버전이 Elasticsearch 버전과 일치하는지 확인 |
| 모바일에서 서버 접속 안 됨 | Tailscale/Cloudflare Tunnel 연결 상태 확인 |
| 데이터가 갱신되지 않음 | 로컬 설치의 경우 앱이 실행 중인지 확인 (꺼져 있으면 폴링 중단) |
| 검색엔진 실행 시 인증 에러 | `MEILI_MASTER_KEY` 또는 `ELASTIC_PASSWORD` 설정 여부 확인 |
| 외부에서 아카이브가 열람됨 | 4-3(포트 노출), 4-5(인증 계층) 설정 여부 즉시 확인 |
| `from:`/`since:`/`until:` 검색이 안 됨 | 날짜 형식(`YYYY-MM-DD`)이 정확한지, 계정명에 오타가 없는지 확인 |
