## 1. 로컬 개발 환경 재기동 (Windows, Docker 미설치 환경)

1. Meilisearch — 프로젝트 루트에서 백그라운드 실행:
   ```
   .local/meilisearch.exe --db-path ./.local/meili_data --http-addr 127.0.0.1:7700 --master-key <backend/.env의 MEILI_MASTER_KEY>
   ```
   (`.local/`은 git-ignore된 영구 로컬 경로 — 세션별 임시 scratchpad에 두지 말 것)
2. 백엔드 — `backend/`에서 백그라운드 실행:
   ```
   npx tsx src/server.ts
   ```
3. 프론트엔드(필요 시) — `frontend/`에서 백그라운드 실행:
   ```
   npm run dev
   ```
4. 확인: 포트 7700/3000/5173 리스닝 여부(`Get-NetTCPConnection -LocalPort <포트>`)로 검증, curl로 실제 응답까지 확인

## 2. Oracle Cloud 서버 재기동 (TODO #20, 상시 호스팅)

**1. SSH 접속** (Windows cmd 기준)
```cmd
icacls "<키_저장_경로>" /inheritance:r
icacls "<키_저장_경로>" /grant:r "%USERNAME%:(R)"
ssh -i "<키_저장_경로>" ubuntu@<public IP 입력>
```

**2. 상태 확인**
```bash
cd ~/<프로젝트_폴더>/docker
docker compose -f docker-compose.yml -f docker-compose.server.yml ps
docker ps -a | grep cloudflared-quick
```

**3. backend/meilisearch가 안 떠있으면**
```bash
docker compose -f docker-compose.yml -f docker-compose.server.yml \
  --profile server-meilisearch --env-file ../backend/.env up -d
```
(데이터는 볼륨에 유지되므로 유실 없음. `restart: unless-stopped`라 보통은 서버 재부팅만으로 자동 복구되고, 이 명령은 그래도 안 떠있을 때만 필요)

**4. Quick Tunnel(`cloudflared-quick`, 도메인 연결 전 임시 노출용)이 안 떠있으면**
```bash
docker start cloudflared-quick   # 컨테이너가 남아있으면 이것만으로 충분
# 컨테이너 자체가 사라졌으면 재생성:
docker run -d --name cloudflared-quick --network <internal 네트워크명> \
  cloudflare/cloudflared:latest tunnel --url http://backend:3000
docker logs cloudflared-quick 2>&1 | grep trycloudflare.com   # 접속 주소 재확인(매번 바뀜)
```
> 도메인 구매 후 Cloudflare Named Tunnel로 전환하면 이 수동 단계 자체가 없어짐(`--profile cloudflare-tunnel`이 `restart: unless-stopped`로 자동 복구).

**5. 문제 생기면 로그부터**
```bash
docker compose -f docker-compose.yml -f docker-compose.server.yml logs backend --tail 50
```
